# Source identity for completed flight logs

Apply the companion source overlay first. Apply `archive-cohorts.patch` to the resulting `orangepi-bin-analyzer` in the staging directory. Inspect with `git apply --check archive-cohorts.patch` before using `git apply archive-cohorts.patch`. The standalone regression runs against that staged analyzer with `CORVON_ANALYZER_SOURCE=/absolute/path/to/orangepi-bin-analyzer python3 -B test_log_cohorts.py` on Linux. It creates temporary synthetic reports and a private in-memory index.

The analyzer reads ArduPilot’s recorded DataFlash `VER.APJ`, `BT`, `BU`, `Maj`, `Min` and `Pat` statistics. A qualifying entry has complete, consistent values for every recorded version message and a matching report/catalog digest. The current advisory group selects CORVON743V2 (1229), ChibiOS (10), ArduCopter (2) and 4.7.3. This identifies the reported target and version. An individual board or a particular binary requires separate evidence. Missing/conflicting metadata remains unassigned. [ArduPilot DataFlash VER fields](https://ardupilot.org/copter/docs/logmessages.html#ver)

The next eligible postflight ingest rebuilds derived profiles from saved summaries, including databases created before this update. `profile/current.json` contains the selected group. `profile/all-boards.json` retains the historical aggregate and group counts. The SQLite `log_controller_groups` index maps every archived log SHA-256 to its group. The selected source-set digest is SHA-256 over the concatenated 32-byte digests sorted by log SHA-256. It changes when membership changes. A new candidate review requires at least one qualifying log and changed membership. The table adds source metadata to the existing catalog. The owner retains the raw archives and the earlier immutable reports.
