# Wired field console R3.4 RC3

The Orange Pi gives changed pixels near a recent tap or the mouse pointer priority. On a large screen change, it can show the first menu item while the full desktop image is still transferring. Exact solid fills and compressed tiles reduce the work needed for flat menus.

Mouse motion over a changing window restores the previous arrow before drawing the new one. When a JPEG or zoom finishes, the sender uses the latest pointer position. Pairing, desktop-owner checks, focused keyboard input and the disarmed-controller guard remain in the normal path.

The companion's optional lossless capture preserves desktop text and edges for the direct USB display. An unchanged image skips re-encoding after the broker checks the owner lease and guard. Large high-entropy captures use the bounded JPEG fallback. The optional window-fit and GTK settings reduce intermediate redraws when opening or switching applications.

The complete archive adds an optional ESP32 application for the E32R35T resistive screen. It can accept a second pending graphics fragment in one pass when both fragments stage bytes, the guard is clear and touch, power and light processing can yield. It leaves the final receipt and any tile that can paint for a fresh UI pass. Its runtime status includes `staging_slice_version` with value `2`. The Pi-only archive works with the previous R3.4 screen application.

See **UPGRADE.md** for offline installation and rollback. The complete archive includes **SCREEN.md** for hardware identification, application verification and restore.
